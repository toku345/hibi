# hibi

仕事終わりに4問へ答え、その日の気持ちや行動をローカルに残す小さなCLIです。生産性や能力を採点するためのツールではありません。まず2週間ほど使い、質問や使い勝手を見直すための最小版です。

構成と処理の流れは、正式ドキュメントの[アーキテクチャガイド](https://hibi-architecture-20261021.toku345.chatgpt.site)で確認できます。Sitesで公開しており、ログインせずに閲覧できます。

## 必要な環境と起動

macOSまたはLinux、OCaml 4.14以上、Dune 3.24以上が必要です。JSONと日時にはYojson・Ptime、端末の行編集にはLambda-TermとLwt・React・Zedを使用します。opamのswitchを用意したうえで、プロジェクトルートで実行してください。

```sh
opam install . --deps-only
opam exec -- dune build
opam exec -- dune exec hibi
```

現在のシェルにopam環境を読み込んでいる場合は、`dune build`、`dune exec hibi`でも実行できます。

## 質問と操作

1. **今日の仕事を終えて、気持ちは？（1〜5）**
   - 1＝とても消耗した、3＝どちらともいえない、5＝とても充実した
   - 成果や能力の自己採点ではありません。
2. **今日やれたこと・頑張ったことは？**
   - 小さな貢献や、踏ん張ったことでもOK。
3. **今日、心が動いた場面は？**
   - うれしい・面白い・モヤモヤなど、どんな感情でもOK。
   - 余裕があれば「何が起きたか → どう感じたか」を一言ずつ。
4. **明日、少し変えてみたいことは？**
   - あればでOK。小さな相談や試みでも十分。

1問ずつ、1行入力してEnterで確定します。3分以内を目安に、短い回答で十分です。空Enter・空白だけの回答はスキップできます。スコアは`1`〜`5`だけを受け付け、不正な入力には短い理由を表示して再入力を求めます。

端末からの入力では、日本語を含む次の基本的な行編集が使えます。

| キー | 操作 |
| --- | --- |
| Ctrl+A / Ctrl+E | 行の先頭 / 末尾へ移動 |
| Ctrl+B / Ctrl+F、左右矢印 | 前 / 後の文字へ移動 |
| Ctrl+H、Backspace | カーソルの前の文字を削除 |
| Ctrl+U | カーソルから行の先頭まで削除 |
| Enter | 回答を確定 |
| Ctrl+C / Ctrl+D | 全回答を保存せず中断 |

質問が終わったときや中断したときは、元の端末設定に戻します。シェル設定ファイルは変更しません。入力履歴をファイルに保存せず、補完や外部エディタ起動も行いません。

全問未回答なら保存しません。Ctrl+C、Ctrl+D、または回答確定前のEOFでは、それまでの回答も保存せず終了します。Ctrl+Dは入力途中でも中断になります。パイプ入力も、最後の回答を含めEnter相当の改行で確定します。評価や追加質問、保存前の確認はありません。

端末から入力しながら標準出力をパイプやファイルに変更する操作（`hibi | tee session.log`、`hibi > session.log`）は、端末の編集・中断操作を保証できないため、保存せずエラーで終了します。

## 保存先とJSON

既定の保存先は`~/.local/share/hibi/`です。`HIBI_LOG_DIR`で変更できます。

```sh
HIBI_LOG_DIR=/tmp/hibi-trial opam exec -- dune exec hibi
```

相対パスはCLIの起動ディレクトリ基準です。`HIBI_LOG_DIR`の空指定はエラーになります。Gitリポジトリ内の保存先は、bareリポジトリやシンボリックリンク経由も含めて拒否します。保存先にはリポジトリ外のディレクトリを指定してください。

必要なディレクトリを作成し、UTF-8のJSONを1回につき1ファイル保存します。新規ディレクトリの権限は0700、ファイルは0600です（umaskでさらに制限される場合があります）。既存ディレクトリの権限は変更しません。ログの外部送信は行いません。

ファイル名は`2026-10-21T18-00-00+09-00-001.json`のように開始日時と連番を含み、同日・同時刻に再実行しても既存の記録を上書きしません。`recorded_at`は質問開始時のローカル日時とタイムゾーンのオフセットです。UTCでは`Z`になります。

```json
{
  "recorded_at": "2026-10-21T18:00:00+09:00",
  "score": 4,
  "accomplishments": "同僚の相談に乗った",
  "moments": "案を見せ合った → 面白かった",
  "next_step": null
}
```

保存成功時は保存先を表示します。入力・保存・後始末に失敗した場合は原因を表示して終了コード1、Ctrl+Cによる中断は130になります。成功と全問未回答の終了コードは0です。

## `hibi`コマンドとしてインストール

```sh
opam exec -- dune build @install
opam exec -- dune install --prefix "$HOME/.local" --sections=bin
```

`~/.local/bin/hibi`へインストールされます。`~/.local/bin`がPATHに含まれていれば、次のように起動できます。

```sh
hibi
```

PATHに含まれていない場合は`~/.local/bin/hibi`で起動するか、利用するシェルの設定でPATHに追加してください。インストール手順はシェル設定を変更しません。

## Entryの生成境界

`Entry`は振り返りの記録1件を扱うモジュール名です。OCamlの言語機能であるレコード型を使って、そのデータ構造を定義しています。

`Entry.t`は「検証済みで、回答が1つ以上ある記録」を表すprivate recordです。フィールドは読み取れますが、外部からの直接生成やレコード更新はできません。

`Entry.create`に開始時刻（`Ptime.t`）、時差、4つの回答を渡します。全項目を検証し、空白だけのテキストは未回答に変換します。非空のテキストは前後の空白を含めて保持します。

- `Ok (Some entry)`：保存可能な記録。`Storage.save`へ渡します。
- `Ok None`：全問未回答。保存先の取得やファイル作成を行いません。
- `Error reason`：不正な値。記録は生成しません。

型は生成経路を制限します。検証関数自体の正しさは、具体例のテストとプロパティベーステストで確認します。

`test/entry_boundary/`の外部クライアントを公開インターフェースのCMIに対してコンパイルし、`Entry.create`の呼び出しとフィールドの読み取りは成功、直接構築とレコード更新はそれぞれprivate recordのエラーで失敗することを確認します。失敗例も型の合う日時・スコアを使い、入力値の不正さではなく生成経路の制限を検証します。終了コードだけでなくprivate recordの診断も確認するため、依存不足や構文エラーではテストは通りません。診断文全体や行番号には依存しません。

このコンパイルテストは入力値が妥当かを判定しません。スコアの範囲、UTF-8、空白の正規化、全問未回答の扱いなどは、引き続き`Entry.create`の実行時検証と既存のテストが担います。

## テスト

プロパティベーステストにはQCheck（`qcheck-core`）、PTYを使う入力テストにはPython 3.9以上も必要です。いずれもCLIの実行には不要です。

```sh
opam install . --deps-only --with-test
opam exec -- dune runtest
```

入力の検証、JSON、日時、保存先の作成、衝突時の既存データ保持、保存失敗・キャンセル時の後始末を検証します。入力テストでは擬似端末を使い、日本語の編集、Ctrl+C・Ctrl+D・SIGINTによる中断、終了後の端末設定の復元も確認します。テストには一時ディレクトリと架空の回答だけを使います。

`test/entry_properties.ml`ではQCheck2の生成器と性質を定義し、8種類の性質をそれぞれ1,000ケース確認します。正常な回答・未回答・不正な値を別々に生成し、生成時の制約、空白の扱い、Unicodeや引用符を含む回答のJSON往復、日時と時差を検証します。不正値の生成器は、反例の縮小後も不正な条件を保ちます。

失敗時はseedと縮小された反例を表示します。表示されたseedを指定すると再現できます。次のseedは実行例です。

```sh
opam exec -- dune exec test/entry_properties.exe -- --seed 437593374
```

### CI

GitHub Actionsでは、PRの作成・更新・再オープン時と`main`へのpush時に、Ubuntu 24.04・OCaml 5.4.1でビルドとテストを実行します。Python 3はランナー付属のものを使用します。

CIに対応するローカル実行コマンドは次のとおりです。

```sh
opam install . --deps-only --with-test --yes
opam install ocamlformat.0.29.0 --yes
opam exec -- dune build @fmt
opam exec -- dune build --profile dev @check
opam exec -- dune build @install
opam exec -- dune runtest --force
```

`dune runtest --force`で、OCamlの具体例・プロパティベーステスト、Entryのコンパイル成功・失敗テストと、PythonのPTYによる端末入力の回帰テストを毎回実行します。コンパイルテストも既存のPython 3とDuneのビルド環境の`ocamlc`を使い、新しい依存パッケージは追加しません。実際の振り返りログや追加のsecretは不要です。

キャッシュは`setup-ocaml`の標準機能だけを利用し、Duneのビルドキャッシュは有効化しません。使用するActionはリリースに対応するコミットSHAに固定し、手動で更新します。

## 整形と静的チェック

OCamlの整形にはOCamlFormat 0.29.0を使用し、`.ocamlformat`でバージョンと`default`プロファイルを固定しています。開発用のopam switchを確認してから導入してください。CLIの実行には不要です。

```sh
opam switch show
opam install ocamlformat.0.29.0 --yes
```

`.ml`・`.mli`の整形と、ファイルを書き換えない検査は次のコマンドで行います。CIでも検査を実行し、整形が必要な場合は失敗します。

```sh
opam exec -- dune fmt
opam exec -- dune build @fmt
```

lintにはOCamlコンパイラの型検査と警告を使用します。Dune標準の設定を継承し、開発用の`dev`プロファイルで未使用の引数・宣言、不正なドキュメントコメント、未使用のmoduleなどの警告（27、32〜39、50、60）を追加しています。有効な警告はエラーとして扱います。専用のlintツールは追加していません。

```sh
opam exec -- dune build --profile dev @check
```

CIでも同じコマンドを実行します。`@check`はリンクを省いた型・警告の検査で、ビルドやテストは別途実行します。今回の整形・静的チェックの対象はOCamlのみです。
